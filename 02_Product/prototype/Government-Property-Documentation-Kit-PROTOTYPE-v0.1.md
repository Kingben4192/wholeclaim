This is **not** the full kit (~116 pp. per the outline). It is a vertical slice carrying one instance of each structural pattern, so a real user can be asked whether the *architecture* works before ~116 pages are written against it.

# A. WHAT THIS KIT IS AND IS NOT

This kit is a documentation and recordkeeping system. It provides a standardized structure for recording the identification, condition, systems, and supporting documentation of a government-occupied facility.

**This kit is not:**

- An official government form. It is not issued by, endorsed by, or affiliated with any agency.
- A compliance certification. Completing this kit does not establish that any statutory, regulatory, or agency requirement has been met.
- A substitute for agency policy, applicable law, procurement requirements, engineering inspections, safety inspections, environmental assessments, or professional evaluations. Where this kit and the user's agency policy differ, agency policy governs.
- Legal, audit, or accounting advice.

The user is responsible for determining what records their agency requires, what retention applies, and whether this format is acceptable for their purposes.

---

# B. HOW TO USE THIS KIT

One binder documents one facility. Campus and multi-building sites use one binder per building.

Complete Section 1 and Section 2 first; they identify the record and are referenced by every later section. Sections 3 through 12 may be completed in any order and are intended to be added to over time rather than finished in a single pass.

Each record entry is dated and attributed to the person who made it. A record without a date and a name is incomplete.

Where a section references another kit in this line, enter the cross-reference identifier if that record exists. If it does not, leave the field blank — do not reconstruct it from memory.

---

# C. RECORDKEEPING CONVENTIONS

These conventions apply to every entry in this binder.

| Convention | Requirement |
|---|---|
| **Ink** | Permanent ink only. Pencil entries are not a record. |
| **Corrections** | Single horizontal strike through the incorrect entry, leaving it legible. Enter the correction adjacent. Initial and date every correction. |
| **Prohibited** | Erasure, correction fluid, obliteration, removal of pages, or backdating. |
| **Date format** | YYYY-MM-DD throughout. |
| **Attribution** | Every entry carries the printed name and title of the person making it. |
| **Signatures** | Signature blocks require an original signature, printed name, title, and date. |
| **Blank fields** | Enter "N/A" where a field does not apply. A blank field is ambiguous; "N/A" is a record. |
| **Continuation** | Where a section is full, continue on a continuation sheet and mark the original "continued on sheet ___". |

**Documentation standard.** The purpose of this binder is not to collect photographs and paperwork. It is to produce a property record that can be understood by personnel who had no part in creating it.

# SUFFICIENCY PROBE — ASSET & INVENTORY SECTIONS (P1–P3)

*Drawn from the Government Asset & Inventory Kit. Included per Decision #118 to test whether the record format closes the failures found in verified public audits. Not part of the Property Documentation Kit.*

**What each probe section is testing, and against what:**

| Probe | Section | Root cause | Verified audit finding it must close |
|---|---|---|---|
| **P1** | Asset Identification Register | **R1** origination failure | MBPO — "did not maintain a complete inventory listing"; "did not immediately tag equipment when received." DANY — "not all tagged assets recorded in inventory records." BOE — 1,176 items never tagged. PAO — "Master Inventory list not accurate and did not include all equipment." |
| **P2** | Custody & Hand Receipt | **R4** custody and location failure | MBPO — "did not store unissued equipment in a secured area." |
| **P3** | Inventory Review & Reconciliation | **R3** no periodic verification | MBPO — "did not perform periodic inventory counts." DANY — periodic counts performed "only on federally-funded items," not the full inventory. |

**The test is not whether the user likes these pages.** It is whether a completed P1–P3 would have prevented the finding in the right-hand column. If a user fills all three in correctly and an auditor could still write the same finding, the format is insufficient and no amount of usability fixes that.

## Validation notes — for the founder, not the user

Things I would specifically watch for when this goes in front of someone:

1. **Does anyone complete Section C's conventions, or ignore them?** The "N/A rather than blank" rule and the correction procedure are the spine of the record's defensibility. If users skip them, the whole institutional posture is decorative.
2. **Does the §4 → §5 register-to-detail link hold?** This is the pattern all five kits share. If a real user maintains the register but not the detail records, or vice versa, the architecture needs rethinking before ~674 pages are written against it.
3. **§9 is the standalone-value test.** If a user photographs or copies this section to keep at a desk, that is the strongest signal in the line — and an argument for it as its own product.
4. **Will anyone sign §13?** A certification block nobody signs is a page of paper. If signing meets resistance, understand whether it is authority, liability, or habit.
5. **The register's 11 columns may be too many for a printed page.** Worth watching whether a real user finds the landscape register usable at actual size, or immediately wants fewer fields. P1 has 13 — if either register gets abandoned mid-entry, column count is the first suspect.

### On the sufficiency probe specifically (P1–P3)

6. **The pass condition is not satisfaction, it is prevention.** For each of P1–P3, the question is whether a correctly completed form would have stopped the auditor writing the finding in the mapping table. Ask the user to read the finding, then ask whether their completed page answers it. If it does not, that is a format failure and no usability improvement repairs it.
7. **Watch the P1 date-tagged / date-entered gap.** That pair is the sharpest instrument in the probe. If users populate one and leave the other blank, the form has reproduced the origination failure it was built to expose — which would be a genuinely useful negative result.
8. **P3's scope field is the DANY test.** If a user runs a partial count and still ticks "entire inventory," the form does not close R3 and the section needs redesigning rather than rewording.
9. **P2 may be the least transferable.** Custody signatures assume an issuing process that not every small jurisdiction runs. If the user has no issuing step at all, P2 tests nothing about the format and something important about the buyer.
