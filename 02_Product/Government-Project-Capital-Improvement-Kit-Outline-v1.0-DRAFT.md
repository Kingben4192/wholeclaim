# Government Project & Capital Improvement Kit — Outline v1.0 (DRAFT)

**Kit 5 of 5**, Government Property & Records Management Kits line.
*A Documentation System for Government Construction, Renovation, Repair, and Improvement Projects*

**Status:** Outline for founder review. No content written, no layout, no visual pass.
**Authorization:** Decisions #110–#113 — Stage 1 (Build) only.

**Lineage:** **replaces** the superseded *Project, Contract & Compliance Record Kit* outline per Decision #113. That kit was contract administration for a contracting officer's representative; this one is project condition documentation for a project or facility manager. Different buyer, different spine. The superseded kit's structural depth is retained where it transfers — schedule, change, inspection, communication and closeout sections — and its contract-administration content (invoicing, modification instruments, compliance requirement tracking, release of claims, deobligation) is dropped.

> **Why the replacement was accepted.** The superseded kit was flagged in its own Stage 1 draft as the weakest product in the line: the no-citations posture cost the most in a contract-administration kit, and agency contract-writing systems already own that workflow. The capital-improvement version is a condition record — *before → during → after* — consistent with the other four kits.

> **Gate anchoring note (#113):** kit numbers are not load-bearing. This kit is referenced by name — *Government Project & Capital Improvement Kit*.

## 0. Format decisions

**Shared with the line** (#112, #113): record-spread architecture, boundary language, recordkeeping conventions, regulatory Posture 1, restrained institutional visual direction — Pine / Ink / Paper, Stamp Red reserved for outstanding-item and deficiency flags, Brass Amber dropped.

**Decided for this kit:**

- **Capacity:** one project per binder. Justification carried forward from the superseded kit's own correction (#112): a project manager administers a small number of projects in depth, not many shallowly. A capital improvement project generates enough progress, change and photographic documentation to fill a binder on its own. Multi-project portfolios use one binder per project.

**Boundary language** — line standard, plus one addition specific to this kit:

> **The kit does not interpret contract terms, determine compliance, or advise on contractual rights or remedies.** It records what the user determines and when.

**Scope note:** property acquired under the project is recorded in the Asset & Inventory Kit; the facility's standing record and its systems in the Property Documentation Kit, which this kit updates at completion; project-related incidents route to the Incident & Loss Documentation Kit; warranty and maintenance handover routes to the Maintenance & Inspection Kit.

## 1. Product definition

**Buyer:** project manager, facility manager, or administrative officer responsible for a construction, renovation, repair, or capital improvement project.

**Job it does:** build the project record while the project is happening — planning, procurement, construction, inspection, change, completion, closeout — so the record explains what existed before, what changed during, and what exists afterward.

**Core principle** (front matter): a project is not fully documented when the work is finished. The record should explain what existed before the project, what changed during the project, and what exists afterward.

## 2. Section structure

### Front Matter — ~4 pp.
Title page · What this kit is and is not (including the interpretation boundary) · How to use this kit · Recordkeeping conventions · Core principle · **Contemporaneous documentation note**: the pre-project condition record cannot be reconstructed after work begins and must be completed first.

### Section 1 — Project Identification & Accountability — ~4 pp.
Project name · Project number · Facility and facility ID · Department or agency · Project manager (name, title, contact) · Designation reference and date · Alternate · Supervisor of record · Contractor (name, identifier, point of contact) · Consultant or designer · Start date · Target completion · Actual completion · Funding source · Fiscal year · Binder serial and volume.

### Section 2 — Project Summary & File Index — ~4 pp.
One-project summary plus navigation, so a reviewer handed the binder can orient in a minute. Project title and number · Facility · Type (construction / renovation / repair / modernization / equipment replacement / site improvement) · Scope in one paragraph · Total value as entered by the user · Period of performance · Current status · Section-by-section index with page references · Volume map where the file exceeds one binder.

### Section 3 — Pre-Project Condition Record — ~12 pp.
The section that cannot be recreated later, and the reason to start the binder before work does. Area or space ID · Property Documentation Kit cross-reference · Existing conditions as observed · Existing finishes · Existing equipment (Asset & Inventory Kit cross-references) · Existing damage · Existing improvements · Measurements where appropriate · Date observed · Observed by · Photograph references · Relevant supporting documents · Notes.

### Section 4 — Project Scope Record — ~6 pp.
Original scope as written · Project objectives · Areas included · Areas excluded · Major components · Exclusions · Applicable project documentation references · Baseline schedule summary · Baseline value as entered by the user · Approving official and date · Scope revision history with reference to §7.

### Section 5 — Milestone & Schedule Record — ~8 pp.
Milestone ID · Description · Baseline date · Revised date · Revision authority and change reference · Actual completion date · Variance in days · Reason for variance as recorded by the user · Predecessor dependency · Impact on subsequent milestones · Status · Verified by and date.

### Section 6 — Progress Documentation — ~14 pp.
The working heart of the binder, filled repeatedly across the project. Date · Work completed since last entry · Work underway · Areas affected · Personnel or crews on site · Photograph references · Delays observed · Issues identified · Inspections performed and reference · Follow-up items · Weather where relevant · Recorded by.

### Section 7 — Change Documentation — ~12 pp.
Change reference number · Change description · Reason · Date identified · Identified by · Related area or space ID · Supporting documentation reference · Approval reference and approving official · Approval date · Cost impact where applicable, as entered by the user · Schedule impact where applicable · Effect on scope · Final disposition · Contractor acknowledgment · Downstream sections updated (checklist) · Effective date.

### Section 8 — Inspection & Quality Record — ~10 pp.
Inspection ID · Date · Type (progress / milestone / acceptance / punch list / regulatory / safety / warranty) · Inspector name and organization · Location or work area · Scope inspected · Standard or specification referenced by the user · Result (accepted / rejected / conditional) · Deficiencies identified · Correction due date · Recheck date and result · Photograph references · Inspector signature · Contractor acknowledgment.

### Section 9 — Project Communication Records — ~12 pp.
Date · Direction (sent / received) · Party (name, organization, role) · Method (email / letter / meeting / portal / phone / site instruction) · Type (notice / meeting record / correspondence / instruction / submittal reference / inspection communication / issue documentation / change communication) · Subject · Summary of content · Action required · Action taken and date · Related document reference · Recorded by. Sized for a full project history — communication volume is the most common gap in a project file at closeout.

### Section 10 — Completion Record — ~8 pp.
Completed work · Final condition by area · Final photograph references · Installed equipment (Asset & Inventory Kit cross-references created) · Major systems installed or modified (Property Documentation Kit updates required) · Outstanding items · Corrections required · Substantial completion date · Final completion date · Accepting official signature and date.

### Section 11 — Project Closeout Records — ~10 pp.
Final inspection completed and result · Punch list closed with date · Warranty information received: provider, scope, start and end dates, document reference · Equipment documentation received · Maintenance information and manuals received · Maintenance & Inspection Kit handover confirmed · Final photographs indexed · Contractor documentation received · As-built documentation received · Final approvals obtained · Outstanding items and responsible party · Property transfer information · Property Documentation Kit updated (Y/N, by whom, date) · File retention determination and disposal-eligible date · Closeout certification signature and date.

### Section 12 — Photographic Documentation — ~14 pp.
Organized as before / during / after, the kit's central evidentiary structure. Photo reference number · Stage (pre-project / progress / completion) · Date taken · Photographer · Area or space ID · View or angle · Subject · Associated milestone, change, or inspection reference · Notes. Mounting pages arranged to allow before/after pairing on facing pages.

### Section 13 — Capital Improvement History — ~4 pp.
A periodic roll-up built from accumulated project records, intended to outlive any single project binder. Major improvements · Renovations · Repairs · Facility upgrades · Equipment replacements · Project costs as entered by the user · Project timing · Changes to facility configuration · Period covered · Compiled by and date.

### Section 14 — Audit Trail & Certification — ~6 pp.
Review date · Reviewer and organization · Review type (internal / IG / external audit / financial / safety) · Scope and period · Documents provided · Findings · Corrective action and due date · Closure date · Signature. Periodic certification statement · Project manager signature and date · Supervisor signature and date · Period covered.

### Appendices A–F — ~12 pp.
A. Project type definitions · B. Change classification definitions · C. Closeout checklist, extracted from §11 as a working one-pager · D. Inspection type definitions · E. Retention schedule worksheet and glossary · F. Blank continuation sheets for §5, §6, §7, §9.

## 5. Open questions

1. **Project size is the remaining capacity variable.** One binder holds one project, but a $30k repair and a multi-year modernization are not the same document. §6, §9 and §12 overflow first. A volume map is sketched in §2; whether that suffices or the kit needs a stated size ceiling is unresolved.
2. **§3 Pre-Project Condition is the kit's strongest argument and its biggest adoption risk.** It has to be completed before work starts, which is exactly when nobody has time. If Stage 2 validation tests one thing in this kit, it should be whether anyone actually fills in §3 on schedule.
3. **This kit creates the most cross-kit obligations** — it writes new assets into the Asset & Inventory Kit, updates the Property Documentation Kit at completion, and hands warranty and maintenance data to the Maintenance & Inspection Kit. That is a strong argument for owning the line, and a genuine failure point if someone owns only this one.
4. **Contract administration is now unserved by the line.** Dropping the superseded kit was the right call for this product, but it leaves the COR buyer with nothing. Whether that buyer is worth a sixth kit later, or is deliberately out of scope, is an open question rather than a settled one.
